## Skills 技能系统 + 桌面宠物

《Chrome 扩展与 Computer Use》给 Codex 补上了操作真实浏览器和整台电脑的手脚。这一篇回到“方法”层面：Skills 技能系统——把你跑通过的流程写成固定的工作规范，让 AI 每次都按你要的方式干活；学会安装现成的社区技能，也学会封装自己的技能。最后做一件轻松的事：给电脑装一只桌面宠物，它除了可爱，还有两个实际用途。

先从“技能到底是什么”说起。

### 11.1 技能是什么

**先看一个你经历过的麻烦**

《办公能力一集讲全》做水印 PDF 时，你把要求说了一长串：每页一张、水印半透明、斜向铺满全屏、文字用自己的名号。效果满意，但下次再做，这一串要求还得原样再说一遍；哪天换了说法、漏了一条，出来的东西就不一样了。流程越常用，重复交代的成本越高。

**技能：给 AI 的岗位说明书**

技能（Skill）就是为这个麻烦准备的：把一套做法写成文件存起来，以后按文件办事。官方给它的定位是“可复用工作流的编写格式”——一个技能就是一个文件夹，核心是一份名为 SKILL.md 的说明文件，里面写清楚要做什么、按什么流程做、有哪些禁忌；旁边可以再配脚本和素材文件，但灵魂始终是那份规范。你可以把技能理解成给 AI 的岗位说明书：能力它本来就有，说明书让它按你的标准发挥。

**能力它有，为什么还要规范**

Codex 本来就会生图、会把图片转成 PDF，为什么还要专门写个技能？因为“会做”和“做成你要的样子”是两回事。直接下指令，它每次都按自己的理解发挥；把角色、步骤、要求、禁忌写成规范，它就大概率按同一套标准出活。如果你在别的 AI 产品里配置过“自定义助手”——设定角色、输出格式、执行步骤——技能做的是同一件事，只是把这些设定存成了可复用的文件。

**平时不占地方，用到才加载**

SKILL.md 的开头有两个固定字段：名字和描述。平时 Codex 手边只放着已装技能的这两行字，用来判断“现在该不该用它”；正文里的完整规范，只有技能真被触发时才会读进来。所以技能装一批在那里，几乎不额外消耗对话的记忆空间——这套“按需加载”的机制不必深究，这里先记结论：技能不是越装越卡。这两个字段长下面这样，位置就在 SKILL.md 的最开头：

![ep11-18](img/11/ep11-18.png)

**两种调用方式**

- **显式调用**——输入美元符号 `$`，唤出已装技能的列表，选中一个回车，后面接上你的要求发送。《办公能力一集讲全》定下的分工在这里正式启用：@ 唤插件，`$` 唤技能，两个符号各管一摊。
- **隐式触发**——不输 `$`，直接把需求说清楚；哪个技能的描述对上了你的需求，它就自己启用。这里的“描述”正是上面说的那个固定字段，所以技能的描述写得准不准，直接决定它会不会被恰当地用起来。

两条路日常都用得上：明确要哪个技能就用 `$` 点名，懒得挑就直接说需求。技能文件夹里还可以放一份进阶配置文件，把隐式触发关掉、只留 `$` 点名调用——进阶用法，普通使用不用动它。

**不点名时，它怎么挑技能**

隐式触发还有一层要知道的事：匹配的依据是各技能的“描述”字段。装了多个同类技能又不点名时，它就在描述都对得上的几个技能里自己挑一个，挑中的未必是你想用的那个。比如你专门装了社区的生图技能 baoyu-skill（装社区技能是 11.3 的内容），生图时只说“帮我画一张……”，它很可能还是调用内置的生图（imagegen）技能，你装的那只反而闲着。想亲眼看一次，等 11.3 装上一个和内置功能同类的技能后，不输 `$`、直接发一条对应需求，看任务过程里它实际启用的是哪个——下面这张实测图里，装着 baoyu-skill 不点名发生图需求，任务里读取启用的仍是内置生图技能：

```
帮我画一张海边日出的手绘风插画。
```

![ep11-19](img/11/ep11-19.png)

所以记一条使用习惯：同类技能装了不止一个时，想用哪个就 `$` 点名哪个；隐式触发留给“哪个都行”的场景。

**先用一次：最小演示**

概念到此打住，动手见一次。随便打开一个项目（技能的产物是实实在在的文件，要落在项目文件夹里），输入 `$`，技能列表弹出来——这就是你机器上已装的全部技能（`$` 列表的样式与各技能的确切显示名，需实机验证）。

在列表里选中生图（imagegen）技能，接着输入这条发送：

```
这个技能能做什么？给我举两个例子，再告诉我怎么用它效果最好。
```

![ep11-01](img/11/ep11-01.png)

它会把这个技能的用途、常见玩法和使用建议讲给你听。这一手是所有技能通用的万能兜底：任何技能不知道怎么用，`$` 选中它问一句就行。

“`$` 选中 + 说要求”这个动作，本篇后面会一直用。

![ep11-02-03](img/11/ep11-02-03.png)

**和插件、MCP 分清楚**

三个词长得像，分工完全不同，用一句话各自站好：

- **技能**——教 AI 怎么干活的工作规范，管的是“方法”：本质是一份文档，把你的流程和标准教给它，让它按你的方式做事。
- **插件**——装上就有的能力包，管的是“分发”：《插件与部署上线》说过一个插件里常装着几套现成的工作方法，那里面的“工作方法”多半就是技能；官方的分工也是这么定的——设计工作流程用技能，要分发给别人装时再打包成插件。
- **MCP**——接外部程序的标准插口，管的是“连接”：让 Codex 能调用外部服务的数据和能力，下一篇《MCP 全解》用一整篇讲透，这里先记住这个三分法。

到这里你已经能唤出技能、问明白它怎么用了。接下来把机器里自带的几个主力挨个认识一遍。

### 11.2 内置技能盘点

**列表里已经躺着一批**

Codex 装好时自带一批内置技能，不用安装就能用。刚才用 `$` 唤出的列表里，主力是下面四个（各技能在列表里的确切显示名与是否有中文名，需实机验证）：

- **生图（imagegen）**——把 ChatGPT 的图片生成能力接进 Codex：能按描述生成新图，能编辑已有图片（换背景、去掉某个物体、改光照和天气），还能批量出成套素材，比如一组游戏道具图标、一批同风格头像。
- **官方文档查询（openai-docs）**——回答“Codex 本身怎么用”这类问题时，先去查官方文档再作答，答案带出处；想确认某个功能的官方口径，`$` 选中它问一句，例如“Codex 怎么安装社区技能”，比凭印象猜可靠得多。
- **技能安装器（skill-installer）**——往 Codex 里装新技能的正式通道：报技能名能装，给 GitHub 地址也能装，不点名直接说“帮我安装××”默认也由它执行，11.3 的社区技能安装全程靠它。
- **技能创建器（skill-creator）**——把你已经跑通的流程封装成自己的技能，创建和更新都用它；动手前它会先和你确认三个问题，11.4 的案例由它主演。

列表里通常还能看到插件创建器（plugin-creator）和代码审查（review-agent）两个，偏开发者使用，现阶段知道名字即可，不影响本篇任何操作。

**案例：生一张自己的壁纸**

拿生图技能跑一单完整的。确认自己在一个项目里，输入 `$` 选中生图（imagegen）技能，接着输入要求发送——画面描述越具体，出图越接近你想要的：

```
生成一张横版图片：一只戴着宇航员头盔的橘猫飘在太空里，背景有地球和星星，颜色干净明亮，
适合当电脑壁纸。
```

任务跑起来后，能看到它调用生图能力工作；完成后图片就落在项目文件夹里，打开方式选默认应用即可查看（产物打开入口的形态，需实机验证）。

![ep11-04-05](img/11/ep11-04-05.png)

文生图带点随机性，第一张和预期有出入很正常：先看主体和构图对不对，再对着成品继续提要求逐项微调，“背景再暗一点”“猫改成橘白相间”。编辑已有图片也是同一个动作——《文件能力一集讲全》整理过的那批照片正好当素材，试一句

```
把项目里的 [某张风景照的文件名] 的天空换成日落，其他保持不变
```

或者发一张参考图，让它照着风格出新图。

**额度提醒**

生图是出了名的耗额度：它一次能生成好几张，但别一上来就要十张。先出一两张验证效果，方向对了再放量——《权限、沙盒与模型》里养成的额度习惯，在生图这里最能省钱。真要批量出成套素材，比如一组游戏道具图标，也先让它出一两个样张，风格确认了再照着样张补齐整套，返工成本最低。

### 11.3 社区技能：来源与安全审查

**内置的不够用怎么办**

内置技能就那几个，而全世界的使用者已经把大量现成流程做成了技能开源出来：爬网页数据的、转文件格式的、做简历排版的……装进来，别人的经验立刻变成你的能力。这一节解决三件事：去哪找、怎么判断能不能装、怎么装。

**三个去处**

- **收集仓库**——GitHub 上专门汇集技能的清单类仓库（常以 awesome 开头命名），量大、按类别整理；页面是英文，用浏览器自带的翻译就能逛。
- **社区汇总页**——Codex 技能的社区目录页，一页页往下加载慢慢翻，新技能上架快，适合定期逛一圈看看有什么新货。
- **技能商店网页**——开源免费的技能商店类网站，默认列出 Codex 可用的技能，还能切换成给其他 AI 工具用的版本；有名的技能基本各家工具都做了适配。

这类站点更替比较快，名称和网址就不写死了：搜索“Codex skills”就能找到当下活跃的入口（以你检索当时可用的站点为准）。

**装之前，先体检**

多数技能只是说明文件，但技能是可以带脚本的——那是能在你电脑上运行的程序。所以立一条安全习惯，和《插件与部署上线》挑插件的信任分级一脉相承：知名的、来源清楚的技能直接装；不知名的小技能，先把它的 GitHub 链接发给 Codex 做个体检：

```
帮我分析这个技能：[技能的 GitHub 链接]。它是做什么的？包不包含要在我电脑上运行的脚本？
有没有需要担心的风险？
```

![ep11-06](img/11/ep11-06.png)

它会读那个页面，把技能的用途、结构和风险点讲清楚。看完体检报告，再决定装不装。

**安装的三条路**

安装统一由内置的技能安装器（skill-installer）执行：报名字、给地址、直接说需求，三条路最终都由它来装。

**有名的技能，报名字装。**输入 `$` 选中技能安装器（skill-installer），后面直接接技能名发送。这条路装的是官方维护的精选技能清单里的成员：不清楚清单里有什么，可以先让它把可装的技能列出来挑；名字不在清单里就装不上，换下一条路即可：

```
$skill-installer [技能名]
```

**小众技能，给地址装。**在技能页面上找到它的 GitHub 目录地址复制下来，交给技能安装器：

```
$skill-installer [技能的 GitHub 目录地址]
```

**懒得点名，直接说也行。**安装这件事本身就归技能安装器管，所以也可以不点名，直接用自然语言提需求。你的需求对上了它的描述，系统默认还是会调用技能安装器来执行安装，效果和 `$` 点名一样，装完同样给出“已安装 ×× 技能。它将在你的下一个任务中可用。”的提示：

```
帮我安装 [技能名] 技能。
```

![ep11-20](img/11/ep11-20.png)

**案例：装一个水印 PDF 技能**

完整走一遍“给地址装”。演示对象选一个“把图片转成带全屏水印的 PDF”的小技能——正好是《办公能力一集讲全》里你手动做过的事，社区里已经有人把它固化成了技能（这类技能不止一个，本课演示用的就是下面地址里的 pdf-generator）。

第 1 步，拿地址。在社区页面打开这个技能的详情，找到它的 GitHub 目录地址，复制。

```
https://github.com/jwynia/agent-skills/tree/main/skills/general/document-processing/pdf/pdf-generator
```

第 2 步，交给安装器。`$` 选中技能安装器（skill-installer），粘上地址发送，看它自动下载安装；装完会提示安装成功、下轮对话可用（完成提示的具体文案，需实机验证）。

```
$skill-installer 安装这个 Skill：
https://github.com/jwynia/agent-skills/tree/main/skills/general/document-processing/pdf/pdf-generator
```

![ep11-08](img/11/ep11-08.png)

第 3 步，确认生效。新开一个对话，输入 `$` 看列表：新技能在，就绪；不在，把应用重启一遍再看。官方口径是新装技能会被自动检测到、检测不到就重启；实际用下来，“装完重启一次”最省心。

第 4 步，用一次。丢一张图进项目，`$` 选中这个新技能，发送：

```
把这张图转成带全屏水印的 PDF，水印文字用“[你的名字]”。
```

![ep11-09](img/11/ep11-09.png)

产物应当是一份带全屏水印的 PDF。对比《办公能力一集讲全》那次“说一长串要求”的做法，你能直观感到技能的意义：流程被别人固化好了，你只管调用。

**翻车实录：第一次失败很常见**

照实说：安装第一次失败很常见，报错信息列出来多半也看不懂。不用研究报错——同样的指令再发一遍，基本第二次就成功了。这不是你操作错了，就是这类安装的脾气。第二遍还不行，再把报错交给 Codex 让它诊断。

**装到了哪里**

社区技能装进用户目录下的技能文件夹，和内置技能分开存放，两个系统的位置不一样：Windows 在 C:\Users\[你的用户名]\.codex\skills，Mac 在 ~/.codex/skills（~ 指你的用户主目录，Mac 侧以实际为准）。知道位置就行，平时不用去动它；以后想彻底删掉某个技能，直接让 Codex 代劳最省事。

### 11.4 自制技能：先跑通，再固化

**从一串重复的要求说起**

回到开头那个麻烦：《办公能力一集讲全》的水印 PDF，每页一张、半透明、斜向全屏、用自己的名号——要求四五条，每次都要重新说。刚才 11.3 装的社区技能能干这事，但参数是别人定的；这一节把你自己的标准封装成你自己的技能，以后一句话出你的标准版。

**方法论先立住：先跑通，再固化**

封装的正确姿势不是凭空造：先把流程手动跑通、把效果调到满意（水印这条流程你在《办公能力一集讲全》已经完成），再把跑通的做法固化成技能。顺序反过来——上来就让 AI 凭想象造一个技能——规范里全是没验证过的假设，用起来处处对不上。先跑通，再固化，这六个字是本节的全部心法。

**动手：封装你的水印技能**

封装用内置的技能创建器（skill-creator），全程对话完成。

第 1 步，把流程说给它。输入 `$` 选中技能创建器（skill-creator），把你跑通的流程和要求完整交代，顺手起个名字：

```
把下面这个流程封装成技能，技能名叫“[你的名字]水印”：把我给的图片合成一个 PDF，每页一张；
每页加一层半透明的全屏斜向水印，水印文字用“[你的名号]”；
输出文件名用“原文件名-水印版.pdf”。
```

第 2 步，回答它的三个问题。技能创建器动手前会和你确认三件事：这个技能做什么、什么时候该触发它、要纯说明文件还是要带脚本——默认纯说明，拿不准就按默认走（三问的实际文案与顺序，需实机验证）。逐一答完，它就开始生成。

![ep11-10](img/11/ep11-10.png)

第 3 步，看看它造了什么。完工后你会得到一个技能文件夹：里面是 SKILL.md，可能还有配套脚本和参数文件。最重要的就是 SKILL.md——打开看一眼，功能描述、触发条件、工作流程，全是你刚才那串要求的规范化版本。文件可以多、结构可以复杂，但一切最终都归结到这份规范文件上。

![ep11-11](img/11/ep11-11.png)

第 4 步，验证一键复用。新开对话，丢一张新图进项目，`$` 选中你的“[你的名字]水印”技能（新技能没出现在列表时，重启一次应用再看，需实机验证），只发一句：

```
处理项目里的 [新图片的文件名]。
```

不用再提任何要求，出来的 PDF 直接带着你的全屏水印。那串说过许多遍的要求，从此存在文件里，不用存在你脑子里。

![ep11-12-1](img/11/ep11-12-1.png)

**改进与更新：重名即覆盖**

用了几次想改规范？拿着最新要求让技能创建器重新创建同名技能：名字一样就是更新，旧版自动被覆盖；名字不一样则是另建一个新技能。这个机制是迭代的正道，也藏着一个小坑——给新技能起名前想一秒，别无意间用重名覆盖了还想留的旧技能。顺带分清：重名即覆盖是技能创建器的脾气；11.3 用的技能安装器正相反，发现同名技能已经装过会直接停下、不做覆盖（需实机验证）。

重建同名技能还能治一个常见毛病：技能装着、`$` 点名能用，但直接说需求时它总不启用。这多半不是坏了，而是当初回答“什么时候该触发”时说得太宽泛，Codex 拿着你的需求对不上号。重建时把触发条件说具体——比如从“处理图片时用”改成“把图片做成带全屏水印的 PDF 时用”——隐式触发就灵了；急用的时候，`$` 直接点名永远管用。

**认知一提：技能可以打包分发**

做好的技能想分享给别人，官方推荐的路径是打包成插件再分发，内置的插件创建器（plugin-creator）就是干这个的。《插件与部署上线》里提过“插件可以自己做”，指的正是这条路。新手阶段知道有这条路即可，等真做出了想分享的技能再回来研究。

### 11.5 桌面宠物

**功能讲完，请一只小伙伴**

这一节给电脑请一只桌面宠物：Codex 桌面应用自带的小动画伙伴，启用后待在你的屏幕上。它主要提供陪伴感，但不只是摆设——有两个实际用处，装好后逐一验证。这是本篇最后一个动手环节，当作放松。

**宠物从哪来：三个来源**

- **内置宠物**——应用自带的一批，设置里点一下就能启用，零安装成本，最适合先试试手感。
- **社区宠物库**——开源社区 Petdex 的图鉴网站，几千只社区制作的宠物任你挑，每只都用一条命令装进来。
- **照片自制**——用一张照片让 Codex 给你生成一只专属宠物，走 hatch-pet 技能，本节最后讲。

**先试一只内置的**

打开设置，在左侧“个人”分区里找到“宠物”一栏（设置 → 宠物，以实际界面为准），列表里就是内置宠物：选中一只，它就出现在屏幕上了。想换一只或者不想要了，回这里改即可。这就是宠物的全部启用逻辑，社区宠物装完也是回到这里选中。

![ep11-13](img/11/ep11-13.png)

**它的两个实际作用**

宠物上屏了，先把它的两个实际用处验证一遍；这两个用处对内置宠物和后面装的社区宠物同样成立。

**作用一：最快的入口。**双击宠物，直接打开 Codex 主窗口。把它放在屏幕角落，你在别的软件里干活时，它就是回到 Codex 的最短路径，比去任务栏里翻图标快。

**作用二：任务消息的通知站。**后台跑着任务、你在忙别的时，Codex 的消息会从宠物身边以气泡弹出来：正在思考、需要你确认……瞟一眼宠物就知道任务到哪一步了，不用来回切窗口（气泡的具体样式与触发时机，以实际表现为准）。

![ep11-17](img/11/ep11-17.png)

**去 Petdex 领一只社区宠物**

想要更多花样，去社区图鉴挑。全流程五步，一次走通。

第 1 步，挑宠物。打开 Petdex 社区图鉴网站，地址是 [petdex.dev](https://petdex.dev)（站点地址曾有迁移，如打不开，搜索“Petdex”以官方最新站点为准）。主页上几千只开源宠物可以预览动画、按名字搜索，还有精选合集。点开心仪的那只进详情页：除了形象展示，页面会给出一条安装命令；有的宠物还支持自选配色，有的不支持，详情页上看得出来（以各宠物页面为准）。

![ep11-22](img/11/ep11-22.png)

![ep11-14](img/11/ep11-14.png)

第 2 步，复制安装命令。命令的形态是：

```
npx petdex install [宠物名]
```

npx 是 Node.js 自带的命令。《文件能力一集讲全》里你已经让 Codex 装过 Node.js，这里直接能用；电脑上没有的话，把这条命令交给 Codex 让它代跑、缺什么让它自己补，还是那个老办法（以实际表现为准）。

第 3 步，终端里粘贴运行。回到 Codex 窗口打开终端窗格——点窗口右上角的底部展开栏按钮，或输入框旁加号（+）菜单里的“终端”（入口以实际界面为准）——把命令粘进去回车。第一次运行，它多半会停在一条类似 Ok to proceed? 的确认提示上——看着像卡住，其实是在等你回答：这是 npx 在问“要不要先下载安装工具本身”，输入 y 回车放行就继续，不是死机。随后是下载安装过程，装完会提示安装成功，并列出后续步骤（确认与完成提示的具体文案，以实际输出为准）。

![ep11-14-1](img/11/ep11-14-1.png)

第 4 步，完全退出重启。装完直接去设置里，多半还找不到新宠物——把应用完全退出再启动：不只是关掉窗口，任务栏托盘里也要退干净。

第 5 步，启用。重新打开应用，设置 → 宠物，新宠物已经在列表里，选中生效。

![ep11-16-1](img/11/ep11-16-1.png)

![ep11-16-2](img/11/ep11-16-2.png)

![ep11-16-3](img/11/ep11-16-3.png)

**翻车实录，还是那句话**

和装技能一个脾气：第一次安装失败很常见，有时报错都没列全，列全了多半也看不懂——别研究，命令再跑一遍，基本第二次就成。装完设置里没有的，九成是应用没退干净，完全退出重启再看。

**用照片孵一只自己的宠物**

Petdex 官方还为 Codex 准备了一个 hatch-pet 技能——它不是内置技能，`$` 列表里没有就先按 11.3 的办法装上——能把照片孵成宠物：家里猫狗的照片、你的手办、甚至一张涂鸦，都能变成屏幕上的动画宠物。

**案例：把一张照片孵成专属宠物。**完整走一遍。

第 1 步，备料。挑一张主体清晰的照片放进项目文件夹：宠物的正面照最好，物件、涂鸦也行。

第 2 步，交给 hatch-pet。输入 `$` 选中 hatch-pet 技能，发送（方括号里换成你自己的）：

```
用项目里的 [照片文件名] 帮我孵一只桌面宠物，形象贴近照片里的样子。
```

![ep11-21-1](img/11/ep11-21-1.png)

第 3 步，等它把流程跑完。孵化是一个多阶段的长任务：先核对素材、生成基准形象，再逐组生成并校验动作与视角，最后组装质检并安装，每一步进度都会报出来；中途它要是弹出选项让你确认，就逐个回答，多数时候它自己往下推进。整个过程要几十分钟（实测约 40 分钟），耐心等它跑完，完成后它会明确告诉你宠物已孵化并安装完成。

![ep11-21-1-2](img/11/ep11-21-1-2.png)

![ep11-21-1-3](img/11/ep11-21-1-3.png)

第 4 步，启用。和社区宠物一样：应用完全退出重启，设置 → 宠物里选中它。

![ep11-21-2](img/11/ep11-21-2.png)

完成标准：屏幕上跑着照片里那位；双击它，Codex 主窗口被直接打开。

![ep11-21-2-2](img/11/ep11-21-2-2.png)

**把你孵的宠物分享到社区**

Petdex 图鉴里的几千只宠物，就是全球用户一只只提交上去的，你孵出的这只同样可以传上去让别人安装。社区由开源贡献者共同维护，四步走完。

第 1 步，去官网点“Submit”。提交入口就在 Petdex 主页（[petdex.dev](https://petdex.dev)）右上角。

![ep11-23-1](img/11/ep11-23-1.png)

第 2 步，登录账号。GitHub、Google、邮箱三种方式任选；以 Google 为例，选好账号、点“继续”完成授权。

![ep11-23-2](img/11/ep11-23-2.png)

![ep11-23-3](img/11/ep11-23-3.png)

![ep11-23-4](img/11/ep11-23-4.png)

第 3 步，找到并上传宠物文件。孵出的宠物存放在用户目录的 .codex\pets 文件夹里，每只一个子文件夹，提交时用的就是它；记不住路径，直接问 Codex 最省事：

```
这个 pets 文件夹在哪？
```

![ep11-23-5](img/11/ep11-23-5.png)

回到提交页点“Pick folder”，选中你那只宠物的文件夹（也支持 zip 包或单独的精灵图）。

![ep11-23-6](img/11/ep11-23-6.png)

第 4 步，核对并提交。页面会在本地检查文件、预览形象，宠物的名字和描述自动带出来；看到“Looks ready to submit”就点“Submit pet”提交（提交后的审核流程与上架时间，以官网当前页面为准）。审核通过后，你的宠物就会出现在图鉴里，安装命令随之生成。

![ep11-23-7](img/11/ep11-23-7.png)

**预期管理：它目前就这点本事**

把话说在前面，免得期望落空：现阶段桌宠的全部能力就是上面两条——双击开窗、消息气泡。右键没有菜单，不能对话，也不会帮你干活。就当一个有点用处的小陪伴，随版本更新它可能获得新能力（以当前版本为准）。

另外认知一提：Petdex 官网还提供一个独立的桌面浮窗应用，装上后宠物会悬浮在屏幕上、跟着 AI 的活动做动作——那是另一个软件，和本节“在 Codex 里启用宠物”是两回事，本篇流程用不到它，逛官网时别误下载。

### 11.6 三个练习任务

下面三个任务把本篇内容完整练一遍。提示词可以直接复制，方括号里的内容换成你自己的。

**任务一：装一个社区技能并跑通一次**

去 11.3 的三个去处里逛一圈，挑一个你真用得上的技能，不知名的先做体检。拿到它的 GitHub 目录地址后，输入 `$` 选中技能安装器（skill-installer）发送：

```
$skill-installer [你挑中的技能的 GitHub 目录地址]
```

完成标准：新技能出现在 `$` 列表里，并且用它完整做成过一件事；如果第一次安装失败、重跑一遍才装上，也算达标——这本来就是常态。

**任务二：把自己常用的一条流程封装成技能**

想一条你已经用 Codex 跑通过、以后还会反复用的流程（水印 PDF、周报格式、图片整理都行），输入 `$` 选中技能创建器（skill-creator）发送：

```
把下面这个流程封装成技能，技能名叫“[你起的名字]”：[写清你已经跑通的完整流程和要求]。
```

完成标准：新开对话，不再重复任何要求，`$` 选中你的技能、一句话得到同样的成品。

**任务三：装一只桌面宠物，验证它的两个实际作用**

去 Petdex 挑一只顺眼的，照 11.5 的五步装好并启用。然后验证两件事：先双击宠物，确认 Codex 主窗口被直接打开；再发送下面这个任务，切去别的软件干活，等它的通知气泡从宠物身边弹出来：

```
把项目里的文件按类型统计一遍，生成一份“文件统计.md”，完成后通知我。
```

完成标准：两个作用都亲眼见过；并且说得出“装完设置里没有”该怎么办（完全退出重启）。

### 11.8 新手常见问题

**Q1：技能装多了会拖慢 AI 吗？**

基本不会拖慢，但会互相干扰。平时每个技能常驻的只有名字和描述两行字，完整规范要等触发了才加载，所以数量本身的负担很小。真正的问题是“抢活”：相近的技能装多了，隐式触发时它可能挑错技能，`$` 列表也越翻越长。处理思路和《插件与部署上线》给插件算三笔账相同——留下在用的，清掉吃灰的；想删哪个，直接让 Codex 帮你删掉对应技能即可；不想删、只想临时停用某一个，也可以让 Codex 去改它的配置把技能停用（进阶做法，以实际表现为准）。

**Q2：社区技能安全吗？**

大部分技能只是说明文件，本身不执行任何东西；但技能可以携带脚本，脚本是要在你电脑上运行的。所以按 11.3 的习惯办：知名、来源清楚的直接装；不知名的先把链接发给 Codex 体检——它是做什么的、带不带脚本、有没有风险点，看完报告再装。另外底线始终在：真到执行敏感操作时，《权限、沙盒与模型》的权限审批照常拦在前面。

**Q3：自制技能需要会写代码吗？**

不需要。全程都是对话：你负责把流程和要求讲清楚，技能创建器负责问三个问题、写出规范文件；就算要带脚本，脚本也是它来写。你真正要出的只有一样东西——一条已经手动跑通、效果确认满意的流程。这也是“先跑通，再固化”的道理：流程本身没调好，封装只会把毛病一起固定下来。另外提醒一句：网上一些老教程会教你手动建技能文件夹、填触发字段，或者写着用 @ 调用技能——都是过时做法，不必照做；在 Codex 里，创建交给技能创建器，调用认准 `$`。

**Q4：宠物会一直占用电脑资源吗？**

它只是一个小小的动画挂件，日常开销很小，正常使用基本感觉不到它的存在（以实际表现为准）。通知气泡只在有消息时才弹，平时它就安静待着。不想要了随时处理：设置 → 宠物里换一只，或者取消选择关掉；哪天想念了再点回来，宠物文件都还在。想临时把它收起来、再唤回来，还可以在输入框试试斜杠命令 /pet（该命令是否可用，需实机验证），不用每次都进设置；全部斜杠命令的清点见《斜杠命令全集》。
