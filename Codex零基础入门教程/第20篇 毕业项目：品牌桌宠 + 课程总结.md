## 毕业项目：品牌桌宠 + 课程总结

最后一篇做两件事。前半篇是毕业项目：做一只自己品牌形象的桌面宠物，再完整体验一次多方案并行开发，全课的新功能到这里全部补齐。后半篇给整套课程做总结：对照总表回收、翻车集锦、数据与隐私、额度总账、跟上迭代的方法、诚实定位。做完这一篇，课程兑现开头的承诺：学完这一套，不用再看第二套教程。

![ep20-01](img/20/ep20-01.png)

### 20.1 毕业项目定位

**为什么是这两件事**

毕业项目不该再学新东西，而该把学过的东西放在一起用。这两件事正好各管一块：品牌桌宠用到的是生图、技能这些内容能力，多方案并行用到的是工作树、云端这些工程能力。

做品牌桌宠，用的全是学过的东西：生图能力出形象，是《Skills 技能系统 + 桌面宠物》练过的；生成宠物走技能流程，还是那一篇的路数；装上桌要过终端粘贴命令那一关，你在领社区宠物时走过一遍。区别在于，那次是把别人做好的宠物装进来，这次从形象到成品全按你的品牌来：头像、配色、气质，都是你自己的。顺着课程回看还有一条线索：从《计划模式》的名片站，到《个人品牌站》的三页站，再到今天的桌宠，你的品牌素材一直在累积，同一套配色、同一个形象气质，这次从网页用到桌面。

多方案并行，则是把《自动化、Git 与远程操控》里工作树的“隔离并行”思想用到完整形态：不但并行，还把任务放到云端跑。那一篇讲启动模式菜单时，“发送至云端”这个选项你已经见过，当时说深入用法留到实战部分，说的就是今天。比稿这件事你在《报价计算器小应用》的工作树里做过一次，这次从本机搬到云上，方案从两个加到三个。这也是全课第一次让项目离开你的电脑去干活，中间会补上最后一块基建：把项目送上 GitHub。

**这一篇怎么走**

结构先交代清楚，路线心里有数。前半篇是两件项目交付：桌宠的定制与上桌分发，多方案并行的完整一轮。后半篇的六节总结，从对照总表回收开始，把翻车救法、数据隐私、额度总账、跟上迭代、诚实定位逐个说透。这六节不引入新功能，讲的全是入口和方法，学过的内容只点名不重讲。最后是毕业验收清单，五项全过，这门课才算真正交付。节奏建议也给一条：前半篇和之前的实战篇一样，先通读再动手；后半篇更像盘库存，不赶时间，一节一节对着自己的使用现状过，哪节和你有关就在哪节多停一会儿。

**动手前提**

三样东西先备好：

- **品牌站项目还在**：多方案并行要拿它的首页当比稿对象；文件夹删了就按《个人品牌站》的兜底办法，花十几分钟重建一个最小版再回来。
- **装过桌宠更好**：《Skills 技能系统 + 桌面宠物》里领过社区宠物的话，终端安装那套流程这次直接复用；没装过也不要紧，本篇从头做自己的，步骤都会给全。
- **额度留出余量**：做桌宠要成批生图，而生图按数倍速消耗额度（倍率以定价页当前说明为准），是全课最烧额度的单一环节；建议挑额度宽裕的日子做，或者拆成两天，今天定形象、明天补动画。

另外提前打个招呼：多方案并行那一节要用到一个免费的 GitHub 账号，这是全课第一次用到第三方开发者账号；没有的话到时候跟着那一节的注册步骤走即可，已经有账号的直接用，不用提前准备什么。

### 20.2 品牌桌宠：形象与精灵图定制

**从领现成的到做自己的**

《Skills 技能系统 + 桌面宠物》给过宠物的三个来源：内置的、社区领的、照片孵的。前两种是“领养”，第三种当时只点到为止。这一节把第三种做透，并且升级要求：不是随便孵一只，而是做你的品牌宠物，配色用品牌主色，形象带上你的标志性元素（logo、招牌道具、名片站头像的同款气质），它站在屏幕上，就是你品牌形象的一部分。

**官方入口，一键起步**

现在有一条比当初更顺的路：打开设置，左栏有独立的“宠物”分区，宠物面板右上角就有“创建”按钮。点它，应用会自动装好 hatch-pet 技能并开一个新对话，你在对话里描述想要的宠物就行。《Skills 技能系统 + 桌面宠物》当时写的是“先输入 `$` 看列表里有没有 hatch-pet”，现在官方把它做成了内置按钮。产品功能就是这样一点点演进的，本篇最后一节会教你怎么跟住这种变化。当然，老办法照样通：输入 `$` 选中 hatch-pet 直接开工，两条路殊途同归。

![ep20-02](img/20/ep20-02.png)

**描述你的宠物**

描述越具体，形象越接近你想要的。名字、物种或形态、品牌元素、气质，一次说全。方括号里的内容换成你自己的，全篇提示词都按这个约定：

```
帮我做一只桌面宠物。
名字叫[宠物名]，形象是[物种或形态，例如“一只圆滚滚的橘猫”]，主色用[你的品牌主色]，
带上[标志性元素，例如“胸口有我 logo 同款的星形图案”]，气质[一句话描述，例如“憨厚安静”]。
参考图在[图片路径，没有可删掉这一句]。
请读取当前安装的 hatch-pet 技能，按它的最新规格制作精灵图，不要自行猜测尺寸或行序。
先出主形象给我确认，确认之前不要批量生成动画。
```

![ep20-03](img/20/ep20-03.png)

提示词里有两句是特意加的纪律。“按 hatch-pet 的最新规格制作”——精灵图的尺寸、行序这类规格数字随版本调整，网上教程里的数字很容易过时，让技能自己读当期规格最稳（具体规格以官方宠物文档与技能当期说明为准）。“先出主形象给我确认”——主形象是后面所有动画的基准，脸型、毛色、比例在这一步锁死，改起来也只是改一张图的事，成本最低。

**先锁主形象，再放量**

主形象出来后别急着说“可以”，对着三个问题看：像不像你要的气质，品牌色和元素在不在位，这张脸你愿不愿意天天看。不满意就在这一步来回改，改到满意再放行。放行之后它会分批生成动画行：待机、左右移动、干活中、需要输入、完成、失败等一组状态动作，每一批都以主形象为参照。生成中途某一行看着不像同一只宠物（角色漂移是常见毛病），当场指出来，点名“保持主形象的脸型、比例和主色”。

![ep20-04](img/20/ep20-04.png)

**逐行检查，三条标准**

全部生成完，它会给你精灵图集（一张把所有动作排成行的大图）过目。逐行检查，三条标准：每一行看起来都是同一只宠物，没有越画越走样；画面干净，没有网格线、文字标签或背景残色混进来；成品文件齐全，宠物包里说明文件和精灵图集都在。哪一行不合格，只重做那一行，已经通过的部分别动，这是省额度也是省心的做法。

![ep20-05](img/20/ep20-05.png)

**它反映的是真实工作状态**

值得知道的是，桌宠的动作不是随机播放的小动画。官方口径里宠物反映对话的工作状态，共四种：干活中（Running）、需要你输入（Needs input）、完成待查看（Ready）、受阻（Blocked）（四态的中文名与展示形态，需实机验证）。几个对话同时有动静时，它按“需要输入优先”的次序提示你，点开宠物旁的活动托盘还能挑对话看。所以检查动画行时，重点核这四态加待机、移动这些基础行为，每个状态都该有对应的动作画面，这只宠物以后是要“上岗”的。

**额度纪律，最后再念一遍**

桌宠制作是全课最烧额度的单一环节，社区实测一只宠物从参考图到上桌能吃掉一大截周用量（具体额度以你的用量页面为准）。四条纪律照做：主形象确认之后再放量生成动画；一轮只改一处；失败只重做那一行；别为“再可爱一点”无限重跑，改到大体满意就收手，额度经不起一轮轮地烧。

### 20.3 桌宠上桌与打包分发

**上桌：老流程复走**

宠物包生成完，安装上桌的流程和《Skills 技能系统 + 桌面宠物》领社区宠物完全一致，复走一遍：把它给出的安装命令粘进终端窗格运行，遇到确认提示输入 y 放行；装完把应用完全退出（托盘里也退干净）再启动；回设置的宠物面板，刷新一下列表，选中你的新宠物。第一次安装失败还是老脾气，命令再跑一遍，基本第二次就成；列表里找不到新宠物，九成是应用没退干净。

装好后顺带认个门：自制宠物存在本机用户目录的 .codex\pets 文件夹里，每只宠物一个文件夹，核心就两件：一份说明文件（pet.json，记着名字与描述）加一张精灵图集（spritesheet.webp）。看见这两个文件，你就明白“一只宠物”的全部家当，待会儿分发出去的也是它们。另外它只存在本机，不会自动同步到 ChatGPT 网页版，换电脑要重装。

![ep20-06](img/20/ep20-06.png)

**验证两个实际作用**

《Skills 技能系统 + 桌面宠物》定过的验收动作，拿自己的宠物再走一遍：双击它，Codex 主窗口直接打开，这是最快的入口；后台挂个任务去忙别的，消息气泡从它身边弹出来，瞟一眼就知道任务到哪一步。斜杠命令那套也还认它，输入 /宠物 可以收起或唤醒（承《斜杠命令全集》）。能力边界也照旧：它的全部本事就是这两条加状态提示，不能对话、不会替你干活，毕业篇也不替它拔高。

![ep20-07](img/20/ep20-07.png)

**两个“上传”，先分清**

想把宠物分享出去，先分清两个容易混淆的动作。投稿社区宠物库，是把宠物提交到 Petdex 图鉴，过审后全世界都能用一条命令装你的宠物，这是“发布作品”。上传到 ChatGPT 网页版，是把精灵图传进你自己账号的网页宠物设置（个性化设置里的宠物一栏，是否开放看账号与套餐，以实际界面为准），只对你自己生效，而且网页版对图片规格另有一套要求，这是“自用同步”。两条路的入口、图片规格和受众都不一样。本节主线走前者。

**投稿 Petdex 社区库**

投稿的完整做法《Skills 技能系统 + 桌面宠物》已经手把手教过：在 Petdex 官网点“Submit”登录，把本机宠物文件夹上传、核对预览再提交。这只品牌宠物照那套流程走即可，这里不再重复。要补的只有一条预期管理：提交后要经社区人工审核才上架，在图鉴里搜不到自己的宠物不是失败，是还在排队（审核流程与上架时间，以官网当前页面为准）。过审之后，你的宠物出现在图鉴里、安装命令随之生成，把它分享给任何人，对方就能把你的宠物装上桌。

从领别人的宠物，到别人来领你的宠物，这一步走完，你第一次给这个社区贡献了内容。图鉴里已有数千只社区宠物（规模与批次以图鉴当前页面为准），从今天起，其中可能有一只带着你的品牌色。

### 20.4 多方案并行：云端三方案择优

**先把项目送上 GitHub**

这一节的主角是云端并行，但开跑前必须补一块基建。云端运行的机制，是在远程容器里取出你放在 GitHub 上的仓库副本来干活：项目不在 GitHub 上，云端就无米下锅。这也是全课第一次用到第三方开发者账号：GitHub 免费账号即可，不需要会任何开发知识，已经有账号的直接跳过下面的注册步骤。《自动化、Git 与远程操控》讲提交推送时说过“需要备份或协作时，再推送到远端仓库”“实战部分真正用到协作时再展开”，现在就是那个时候。

**注册一个 GitHub 账号**

GitHub 是全球开发者存放代码的网站，云端任务靠它中转你的项目。注册免费，几分钟能走完；官网是英文界面，看不懂就开浏览器自带的网页翻译，照样能填（页面文案与步骤以官网当前版本为准）：

1. 浏览器打开 github.com，点右上角的 Sign up（注册）。
2. 按提示逐项填写：邮箱填你常用的，稍后要收验证码；密码它会实时提示强度够不够；用户名全站唯一，用好记的字母数字组合，提示被占用就换一个；国家/地区按实际选，填完点 Create account（创建账户）。
3. 过一次人机验证，通常是个小拼图或图片题，按提示操作即可。
4. 去邮箱收验证码，回到页面填入，账号就建好了；随后的偏好问卷、方案选择一类页面，一路选免费、能跳过的都跳过。

![ep20-10-0](img/20/ep20-10-0.png)

![ep20-10-1](img/20/ep20-10-1.png)

注册完成后保持登录状态，接下来的授权环节直接就能用。剩下的体力活让 Codex 代办。进入品牌站项目，发送：

```
把当前项目发布到我的 GitHub 账号：如果电脑上还没有 GitHub 命令行工具就先帮我安装，
然后引导我完成登录授权；之后在我的账号下新建一个私有仓库，把项目完整推送上去。
每一步做了什么用一句话告诉我，需要我在浏览器里确认时提醒我。
```

它会在终端里装好 GitHub 命令行工具，再拉起浏览器走设备授权——页面上确认账号、填入终端给出的一次性代码、点一次授权即可；随后建仓、推送一气呵成，最后交回发布完成回执，装了什么版本、登录的账号、仓库名、推了多少文件、本地与远程提交是否一致都在里面。《自动化、Git 与远程操控》里装 GitHub 命令行工具处理 PR 的先例，套路一模一样：命令的事交给它，你只负责在浏览器里点确认。推完可以问一句“仓库地址是什么”，打开看一眼自己的项目躺在 GitHub 上；这块基建以后所有云端任务都用得上。

**连接云端，创建环境**

第二步前置，让云端认识你的仓库。入口就在桌面应用里：新建对话，点开输入框旁的工作位置菜单，四个选项一字排开——本地、新建本地工作树、关联 Codex Web、云端，没关联前“云端”是灰的。选“关联 Codex Web”，它会打开 Codex 的网页端：页面上点“连接到 GitHub”，看完连接器的权限说明点“继续连接到 GitHub”，再在 GitHub 页面点一次 Authorize 完成授权；回到 Codex 网页，输入框旁出现“选择代码仓库”，连接就成了；点开它，选中你的品牌站仓库和 main 分支。仓库范围的授权在选仓库时按需给。连接完成还差最后一小步：在 Codex Web 里为你的仓库配置运行环境——菜单里“关联 Codex Web”的悬浮提示写得直白：“通过 Codex Web 配置环境以启用任务云端派发”，环境配好之前“云端”一直是灰的。环境具体怎么建，下面开跑前的第一步就是它。这些都是一次性的，配好以后开云端任务就是一句话的事。

**三个方案并行开跑**

基建齐了，回到桌面应用做正事：给品牌站首页比稿。新建对话，点开工作位置菜单选“云端”——就是《自动化、Git 与远程操控》里见过的那一项，之前一直灰着，今天第一次真用。头一回给品牌站开云端，先给它建个环境：输入框旁点开环境选择器，点“＋新建”，它会打开 Codex Web 的环境页——表单里选中你的品牌站仓库，名称用默认生成的，其余一路默认，拉到底点“创建环境”；建好回桌面，在环境选择器里选中这个新环境，输入框旁的徽章换成品牌站仓库，就绪。

提示词按这个模板，方括号换成风格方向：

```
把首页改成[风格方向，例如“活泼卡通”]的视觉方案：只改首页，

```

![ep20-12-4](img/20/ep20-12-4.png)

同样的模板再开两个云端任务，风格方向换掉，比如一个“极简黑白”、一个“活泼卡通”。三个任务各自在独立的云端容器里跑，互不影响，你的本机文件更是一个字都不会动。有三件小事这里交代掉：

- **规矩文件的配色禁区**：《个人品牌站》给项目锁过“配色不许改”，而《AGENTS.md、Diff 与还原》讲过，你在对话里的明确指令优先级更高，这轮比稿是你亲口要求的换风格，它一般会照办；真被规矩拦下，把那条禁区临时放开，比完稿选定方案后再锁回。
- **选错运行目标不用重打字**：启动模式选错了或者手滑点了取消，不用重新打一遍提示词，在输入框按上箭头能找回刚发过的内容，换个环境再发一次即可。
- **云端干活阶段默认不联网**：装依赖这类要进网的事它在干活阶段做不了，我们的静态页面项目用不到联网，知道有这回事即可，以后做别的项目遇到再回头看这句。



另外顺带知道：除了三个提示词各开一个任务，云端还支持同一个任务一次跑出多个尝试、供你挑最好的一版（多次尝试的入口与形态，以实际界面为准）。思路同源，本篇选三提示词的做法，风格语义更直观。

**并排验收，挑一个**

三个任务陆续跑完，每个都交回一份总结加一份改动清单（diff）。云端任务偶发失败也正常——列表里挂出 ERROR 的，同一条提示词重发一次即可，失败记录留在列表里不碍事。在任务列表里并排过一遍：先读总结看它对风格的理解，再扫 diff 看动了哪些文件。《报价计算器小应用》里两个界面方案比稿的验收思路，搬到云端原样适用。挑出你最中意的那版；挑不出就看哪版最接近你当初给《个人品牌站》定的气质，比稿挑的是方向，方案本身不用完美。

**云端与工作树，怎么选**

两种并行做的是同一件事，只是跑的位置不同，对照着记：

- **相同的做法**——都是从一份基线出发开隔离副本，各改各的互不打扰，最后择优收回；《自动化、Git 与远程操控》的工作树是本地版，本节是云端版。
- **前置不同**——工作树只要项目在本机，零门槛；云端要项目在 GitHub、配好环境，第一次有基建成本。
- **节奏不同**——工作树在你电脑上实时跑，随时能旁观插手；云端是异步收货，交出去就去忙别的，回来看结果。
- **占用不同**——工作树占本机资源，开多了电脑吃力；云端不占本机，电脑关了它照样跑，《自动化、Git 与远程操控》常见问题里“定时任务电脑关机还会跑吗”的出路就在这里。

选路口径一句话：改动小、要实时来回的，用本地或工作树；任务长、要多方案比稿、人不在电脑边的，上云端。额度上记一笔：云端任务和本地消息共用同一个用量窗口，三方案并行等于一次花三份，比稿别贪多。

### 20.6 翻车集锦与排错三板斧

**全课翻过的车，集中过一遍**

这门课从没假装一次成功。把各篇真实翻过的车集中到一起看，救法其实早已成套。每一条都按“现象、当时怎么救”来记；六个案例本身不用背，要带走的是它们背后同一套动作：

- **部署完打开是空白页**（《插件与部署上线》）——截图丢回对话，让它读部署日志归因：多半是发布目录指错、首页文件不在预期位置，补上配置重新部署。
- **网页读取被风控验证拦住**（《内置浏览器全解》《调研情报系统》）——不是故障是常态，换 Chrome 扩展路线用你已登录的浏览器继续。
- **装宠物、装技能第一次失败**（《Skills 技能系统 + 桌面宠物》，本篇上桌时可能重演）——命令原样再跑一遍，多数第二次就成；装完找不到，先查应用退干净没有。
- **多页站子页打不开、导航断链**（《个人品牌站》）——发布目录、相对路径、文件名大小写逐个排查，每页点一遍是上线最后一步。
- **定时任务到点没跑**（《自动化、Git 与远程操控》《报表自动化流水线》）——先查三前提：电脑开着、应用在跑、项目还在原位；错过的不补跑。
- **算错了价或改坏了页面**（《报价计算器小应用》）——先按边界值清单逐项试算，把算错的地方一条条暴露出来，让它按试算结果修正；真要退掉某处改动，用《AGENTS.md、Diff 与还原》的三档还原兜底。

**排错三板斧**

集锦里的救法五花八门，底下其实是同一套顺序，遇到新问题照这三步来：

1. **看报错原文**——别扫一眼就关。报错里通常写着是谁、在哪一步、因为什么出的错，看不懂就整段复制去问它。
2. **查额度状态**——输入 /状态 看当前额度和模型挡位（《斜杠命令全集》讲过；Windows 上偶尔不显示，再点一次就好）。相当一部分“它不干活了”其实是额度见底。
3. **重启重登**——应用完全退出再开，还不行就登出重登。环境类的小毛病大多到这一步就消失了。

这个顺序本身就是排查逻辑：先弄清它报了什么错，再确认额度还够不够，最后排除环境的小毛病。顺序别倒过来，一上来就重启，报错原文没了，第二次翻车连线索都不剩。

三板斧之外还有一个万能兜底，《认识与装好》就教过：把报错或异常截图直接丢回对话，把它当聊天窗口用，“这是什么意思，怎么办”。另外两个官方口径的小知识备着：对话半天不动，先看是不是在等你审批权限，再新开个小对话换个问法试试；发现命令行版本有的功能桌面版还没有，那是两边发布节奏不同步，不是你的坏了。真遇到疑难杂症，输入 /反馈 生成反馈编号去官方仓库提问题，编号能帮官方定位你的现场。

### 20.7 数据与隐私

**把问题拆成三层来看**

“我的东西安不安全”是零基础读者最担心、教程又最少讲的问题。把它拆成三层，每层各有各的答案，混在一起才吓人：

- **第一层，它能动我电脑上的什么**——权限和沙盒管的事，《权限、沙盒与模型》整篇讲的就是它：不给权限的目录它进不去，写入要过你的审批。这层不重讲。
- **第二层，我的内容去了哪**——你发的提示词、交给它的文件内容、对话上下文，会送到云端的模型做推理。这是产品的工作原理，就像你把问题发给任何在线服务一样：“想”这一步发生在云端，不在你的电脑里。
- **第三层，我的内容会不会被拿去训练模型**——多数人真正想问的是这层，也是本节的重点：有一个开关，主动权在你手里，下面单独讲。

**训练开关在哪，怎么设**

开关叫“为所有用户改进模型”（Improve the model for everyone），入口在 chatgpt.com 网页端：左下角点自己的昵称，进“设置”，选“数据管理”分区，第一条就是它。这是账户级设置、全设备同步，网页改了桌面一并生效（桌面应用里若有同名入口，改哪边效果相同）。官方口径明确它同时管 ChatGPT 对话和 Codex 任务。开着，代表愿意让自己的内容帮官方改进模型；关掉，内容不再用于训练，功能不受任何影响，历史记录也还在。开还是关没有标准答案，知道它在哪、按自己的意愿设置过，这一节的目的就达到了。

![ep20-16-1](img/20/ep20-16-1.png)

![ep20-16-2](img/20/ep20-16-2.png)

还有四件事一并知道：临时聊天默认不用于训练，聊天记录也只保留一段时间就删；**点了赞或踩的对话例外**，你主动给了反馈，那段对话就可能被用于改进模型，即使总开关是关的，给反馈前知道这回事；公司购买的团队版、企业版工作区默认就不用于训练；隐私门户里另有一个“请勿用我的内容训练”的总开关，和应用内开关是两个入口，顺带知道即可。

**授权撤销总盘点**

这门课陆续给出去不少授权，毕业前盘一次总账，知道每一样在哪收回（各入口的现行文案与位置，需实机验证）。先看应用和项目层面的四样，自己动手就能收回：

- **文件夹权限**：敏感文件夹从一开始就别给，这是《权限、沙盒与模型》立的规矩；已经给了的，从项目列表移除即可。
- **插件**：插件面板里可以断开连接或卸载，《插件与部署上线》装的 Netlify 之类都在这管。
- **MCP 服务**：设置或配置文件里移除对应条目，《MCP 全解》怎么加的就怎么减。
- **内置浏览器登录态**：浏览器里登出网站或清掉浏览数据，《内置浏览器全解》导入的 Cookie 也随之失效。

再往外一层，是浏览器和系统级的三样，入口深一点，也都有得撤：

- **Chrome 扩展**：浏览器的扩展管理里移除；它的电脑控制权在设置“集成”下的“电脑操控”分区收回，Chrome 一栏右侧直接关，点“管理”可细调（《Chrome 扩展与 Computer Use》）。
- **Computer Use**：同在“电脑操控”分区，关掉“任意应用”总开关即可；Mac 上另有系统级的屏幕录制与辅助功能权限，在系统设置里撤（Windows 无对应的系统级授权项）。
- **GitHub 与云端**：云端设置页里能解除仓库授权、删除环境，本篇刚给出去的这份也随时能收回。

记忆功能默认关着、可整体重置，《上下文与记忆》讲过，指回不重讲。这张盘点表的用处是让你确认：每一份授权都有回收入口，不存在“给出去就收不回”，要不要撤、什么时候撤都由你。

### 20.8 额度总账

**限额的结构，先看懂再谈够不够**

额度焦虑大多来自看不懂结构。现行结构三句话：限额按模型挡位分别计算，在一个滚动的时间窗口里累计（现行是五小时一档，另有周上限，结构与数值以定价页为准）；本地消息和云端任务共用同一个窗口，上一节三方案并行一次花三份，就是这个意思；超出包含额度后可以买用量点数（credits）续，不同挡位的费率差着数量级，轻量挡位远比旗舰挡位耐用。再加一条本篇的切身体会：生图按数倍速消耗，做桌宠时额度确实下得快。

**看用量的三个入口**

- **用量仪表盘**：浏览器打开 chatgpt.com/codex/settings/usage，用量走势一目了然；官方建议每一两周看一次，掌握自己的消耗节奏（页面形态以实际界面为准）。
- **应用内使用情况页**：设置左栏的“使用情况和计费”，累计消耗和近期活动都在。
- **斜杠命令**：输入 /状态 随手查当前窗口余量，《斜杠命令全集》教过；Windows 上偶尔不显示，再点一次。

**正面回答：Plus 够不够**

这门课的用法（单任务型、学习节奏、偶尔并行），一个普通订阅挡位从《认识与装好》一路用到这一篇，全部项目做得完，这是课程实际走下来的账（你的具体余量以自己账号页面为准，不同时期政策有别，不做绝对承诺）。什么时候才需要考虑升级：天天多方案云端比稿、长任务连轴转、拿它当团队生产力工具的重度用法。普通学习和日常使用，先把手里的额度用明白再说。真撞了限额也有三条出路：等窗口滚动重置、把不要紧的任务换到轻量挡位、买用量点数应急；长期重度另有接 API 按量计费的路线，顺带知道即可。

**省额度习惯，最后复盘一遍**

先复习三条老习惯：

- **挡位按需**：普通任务用轻量挡，难题才上旗舰挡，《权限、沙盒与模型》的老口径，一直是省额度第一招。
- **一事一对话，及时压缩**：对话拖长消耗涨得快，《上下文与记忆》教的压缩和开新窗别忘了用，越到长项目越管用。
- **测试任务用完就删**：定时任务里的试验品别留着空跑，《自动化、Git 与远程操控》《报表自动化流水线》都提过，删一个是一个。

再补三条，两条来自本篇的切身账，一条是官方建议里课程还没点过名的：

- **生图先样张后放量**：从名片站头像到本篇桌宠，一路都是这条纪律省下的额度，生图越多的项目越要守。
- **不用的 MCP 服务停掉**：挂着的服务白占上下文也拖累消耗，官方省额度建议里点过名，课程前面没讲过，这里补上。
- **规矩文件别无限膨胀**：AGENTS.md 每次任务都随行，越长消耗越多，只写要紧的，《AGENTS.md、Diff 与还原》的老话。

### 20.9 毕业后跟上迭代

**为什么这是最后的必修课**

这门课录制期间，产品自己就大变过一次样：Codex 并入 ChatGPT 桌面应用，全网旧教程的截图一夜过时，《认识与装好》里你装的就是新形态，而当时多数教程还在教旧的。而且这不是十年一遇的大事，小到一个入口改名、一个默认值调整，每周都在发生，靠等别人更新教程，永远慢半拍。这门课也终有变旧的一天，所以最后一门必修课教的是方法：新东西出来，你自己就能跟上，不用等别人更新教程。

**官方两个入口，读法有分工**

跟更新只需要盯两个官方页面。`What's new` 是每周摘要，挑要紧的新能力用人话讲，常配着示例提示词，适合每周扫一眼标题；Changelog 是全量流水账，桌面、命令行、手机端分列，每个版本改了什么全在，适合从摘要里看到相关条目后点进来查细节（桌面应用内有没有更新日志的直达入口，需实机验证；没有就收藏这两个网页）。读法就一句：先扫每周摘要的标题，和自己用法有关的，再去流水账里看细节，其余略过。筛选标准也只有一条：改没改你每天用的入口、动没动你固化的任务；无关的条目扫过标题就翻篇，跟更新每周只花几分钟。

**更新日志不只报喜，还保你不掉坑**

举个课程期间的真事：官方在更新说明里提前预告某个模型将从 Codex 退役，连替代模型都写明了。《报表自动化流水线》里提过一句机制，定时任务里显式选过的模型可能退役、任务要跟着换，那句话的情报来源就是更新日志。只看“上了什么新功能”会错过这类关键提醒：你固化的任务、你依赖的入口，变动都会先出现在这两个页面上。

**四层讲法：自己拆新功能**

看到一条新功能，怎么把它变成自己的能力？用这门课讲每个功能的同一套框架拆它：是什么、怎么用、什么时候该用什么时候不该用、翻车了怎么救。不用自己闷头研究，让 Codex 陪你拆：

```
这是 Codex 本周更新说明里的一条：[贴上原文或链接]。
请按四层帮我拆解：一，它是什么，用一句人话加一个类比；二，怎么用，给我能直接照做的步骤；
三，什么时候该用、什么时候不该用；四，可能翻车的点和对应救法。
最后给我一个五分钟能完成的上手小任务。
```

拆完照着小任务动一次手，这条新功能就是你的了。第一次练手别挑大的，选一条一句话能说清的小更新，五分钟拆完、五分钟上手，方法就学到手了。这套框架就是本课二十篇的讲法本身：学会了它，新功能出来你自己就能拆明白、用起来，“不用再看第二套教程”说的就是这个。

### 20.10 诚实定位与分工

**它适合谁**

这门课不夸大、不贬低，最后把定位说透。Codex 适合三种人：零基础、不想为“会用 AI 干活”先去学一套开发工具的人；已经为 ChatGPT 付费、想让订阅多干活的人（Codex 包含在订阅里，零新增成本）；要的是“交办任务、收回成果”而不是盯着屏幕逐行改的人。你一路学下来的一句话交办、计划对齐、验收成果，就是它的常规用法。反过来说，如果你本来就整天泡在代码编辑器里、要的是逐行掌控，这门课的许多讲法对你是绕路，市面上有更对口的工具和教程。

**短板照实说**

- **版本管理依赖 Git**——工作树、还原、审查面板这些好东西都建立在 Git 上；课程把这道门槛藏进了流程里，但门槛本身还在，项目做深了绕不开。
- **换第三方模型要折腾**——想接别家模型有路可走，但要动配置文件，对零基础不友好；第二季会展开，现阶段照实说：不方便。
- **上下文相比部分对手偏小**——长对话更容易“变笨”，《上下文与记忆》教的压缩和开新窗就是为这条短板准备的（具体容量随模型代际变，以当期说明为准）。
- **“没有内置编辑器”是旧账，已过时**——早期评测常提这条，如今 Diff 面板里可以直接手改，《AGENTS.md、Diff 与还原》里你亲手用过。引用旧评测前先核日期，这也是上一节“识别过时信息”的现场练习。

**和别的工具怎么分工**

市面上常被并提的三个工具，一句话各归各位：Cursor 是给写代码的人用的 AI 编辑器，主场在逐行改代码、盯着改动看；Claude Code 是终端里的命令行助手，主场在大型代码库的深度改造；Codex 的主场是你现在熟悉的样子：交办任务、异步收货、包在 ChatGPT 订阅里。按这门课的受众翻译一下：你不写代码，用不上编辑器；你要的是收成果，不是过程控制；你已经付了订阅费。所以对你而言这不是三选一的难题。身边有开发者朋友问起，按“他整天写代码就推编辑器路线、他要改大工程就推终端路线、他像你一样要交办收货就推 Codex”给建议即可。三个工具没有唯一赢家，各有各的适用场景；它们都在快速迭代，今天的分工边界明天就可能挪动，记住场景、别背结论，隔段时间用上一节的方法自己复核一遍。

这套定位与分工的说法别硬背，自己演练一遍才算数。开个新对话，让 Codex 当陪练：

```
你扮演一位整天用代码编辑器写代码的开发者朋友。我用三分钟向你介绍 Codex：
它适合谁、有哪些真实短板、和你手里的工具怎么分工。听完后你提两个追问，
再按“适合谁 / 短板 / 分工”三项给我的介绍打分，指出我说得最含糊的一条。
```

演练一轮，哪条被追问问住，就回对应的节再看一遍——毕业验收清单里“不看稿讲三分钟”考的就是这一手。

**第二季预告**

有几个方向这门课刻意没展开，留给第二季：子代理（Subagents，让多个 Codex 分工协作）、钩子（Hooks，在任务的关键节点自动执行你的规则）、自定义模型接入、后端与数据库、复杂数据分析、团队治理。这些功能大多已经在产品里，都建立在这二十篇打下的基础上；基础已经够用，想学的时候随时能接上。

### 20.11 毕业验收清单

最后一份清单，验的是你这门课的毕业资格，不再针对单个项目。逐项真做，做不到的回对应节返工：

- **品牌桌宠已上桌，两个实际作用验证通过**——判定标准：屏幕上待着的是你品牌形象的自制宠物，不是内置或领养的；双击它能打开主窗口；后台跑任务时状态气泡会从它身边弹出。差哪条回 20.2、20.3。
- **独立发起过一次多方案并行，并择优合入**——判定标准：任务列表里有你同时发起的多个方案；本地项目里有 apply 拉回的那一版，页面上看得见；能用一句话说出为什么选它淘汰另外两个。走不通回 20.4。
- **功能覆盖对照总表全部打勾**——判定标准：20.5 那张表逐行都能答上“在哪篇学的、会不会用”；有虚勾的行，回对应篇补完那个点再勾。
- **数据与隐私的关键开关逐项检查过**——判定标准：训练开关按自己的意愿设置过一次；授权盘点表逐行知道入口在哪；能说出“权限管动作、开关管数据”这两层的区别。含糊的回 20.7。
- **能向别人说清它适合谁、短板在哪、怎么分工**——判定标准：不看稿讲三分钟，说得出至少两条真实短板；朋友是开发者也能给出分工建议。卡壳回 20.10。

五项全过，恭喜毕业。这张清单本身也值得留下：先定验收标准、再动手做事、逐项诚实核对，这个习惯往后做什么都用得上。

### 20.13 新手常见问题

**Q1：桌宠形象不满意，能反复改吗？**

能，但要按纪律改。最便宜的反悔点在主形象确认那一步，多花心思都值得；上桌后局部不满意，只重做不满意的那几行动画，别整只重生成；整体气质都不对，才值得推倒重来。每一轮生成都实打实烧额度，动手前先想清楚这轮只改哪一处。改完重新打包安装、退出重启后在设置里选中新版即可（旧版本的覆盖与共存表现，以实际界面为准）。

**Q2：云端并行和本地工作树并行，怎么选？**

一句口径：改动小、要实时来回看的，用本地或工作树；任务长、要多方案比稿、人不在电脑边的，上云端。两个提醒：云端有前置门槛，项目要先推上 GitHub、配好环境，工作树零门槛开箱即用；额度上云端任务和本地消息共用窗口，并行开得越多花得越快。拿不准就先工作树，用出“不够用”的感觉再上云端。

**Q3：对照总表有几项打不了勾，算毕业吗？**

算不算，表说了算，但打不了勾不等于重修。回到那一项对应的篇章，只补那一个点，通常是一节内容、十几分钟的事，补完就能勾。真正不算毕业的只有一种情况：明知答不上“会不会用”还把勾打了。这张表最后是给你自己用的，对自己诚实，它才有效。

**Q4：学完这套课，下一步学什么？**

三个方向按优先级排：最要紧的是把五个实战项目换成你自己的真实需求各做一遍，品牌站换成你的主业展示、流水线换成你每周真正重复的事，用起来才算学会；然后用 20.9 的方法每周跟住更新，新功能出来自己拆；最后才是等第二季展开子代理、钩子那些进阶方向。也别急着学新的：先让手里这二十篇的能力在生活和工作里真正用起来，用熟了再考虑扩展。
